# ChessX 系统设计规格

**版本**：v1.0
**日期**：2026-09-30
**文档性质**：交付执行 Agent 的实现规格

---

## 1. 系统定位

ChessX 是一个**基于棋盘的叙事模拟系统**。棋子沿用国际象棋的走法作为移动规则，但它不是国际象棋——系统不判定吃子，不判定输赢，不判定棋局优劣。

系统的职责边界：

| 系统负责 | 系统不负责 |
|---|---|
| 维护棋盘、棋子位置、object 状态的权威数据 | 判断什么是重要的、什么是有价值的 |
| 校验并执行规则 | 对角色行为给予奖励或惩罚 |
| 仲裁冲突，把意图转化为既成事实 | 决定角色应该有什么动机 |
| 记录发生的事 | 判断发生的事是好是坏 |

**角色的奖惩机制存在于角色自身**：它们如何回应背叛、死亡、馈赠，由各自的价值观决定。当一颗棋子杀死另一颗棋子时，它感到惶恐还是兴奋，不由系统规定。

**规则的作用是扩展叙事的可能性空间，不是收敛它。** 规则必须保持价值中立：规则只声明世界中存在什么，不声明什么值得追求。

## 2. 核心概念

### 2.1 棋子（Piece）

棋盘上的行动主体，由 LLM Agent 驱动，是叙事的基本单位。

每颗棋子由两部分定义：

| 部分 | 格式 | 内容 | 可见性 |
|---|---|---|---|
| 公开信息 | JSON | 类型、颜色、初始位置 | 全局可见 |
| 私人信息 | Markdown | 性格、公开目标、隐藏目标 | 仅该棋子可见 |

**类型（type）只定义行进方式**，与人设、性格、目标无关。类型在初始配置时指定，除系统规则特别说明（如兵到底线升变）外不可更改。

**颜色（color）是纯标签**，用于标示身份，类似国籍。颜色在系统中不承担任何判定职责：**同色棋子可以互相攻击**；移动路径上的交涉**无论双方是否同色都会触发**。棋子可以改变自身颜色，权限在棋子自己手里；改变颜色不产生任何规则层面的后果。

棋子数量上限为 8，可以少于 8，也可以为空。

### 2.2 目标（Goal）

每颗棋子持有两类目标：

- **公开目标**：写在私人信息中，角色可以对外宣称；
- **隐藏目标**：只有该棋子自己知道。

目标的内容、数量与措辞由人设文档自由定义，系统不限定形式。目标的更新规则见 §8.2。

### 2.3 回合（Turn）

系统的时钟单位。一个回合内，所有可行动的棋子各行动一次。

### 2.4 休息（Rest）

棋子移动后进入休息状态。处于休息状态的棋子**不能移动**，但可以交谈、可以被搭话、可以被路径交涉命中。

### 2.5 交涉（Negotiation）

当移动中的棋子其路径上存在休息中的棋子时，双方进入交涉。交涉是解决**通行冲突**的机制。

交涉分为两类，由**移动发起前**双方的攻击能力关系决定：

| 类别 | 判定条件 | 决定权 |
|---|---|---|
| **平等交涉** | 双方都能攻击到对方 | 双方协商共同决定 |
| **优势交涉** | 只有一方能攻击到对方 | **能攻击的一方单方面决定** |

交涉的结果只有两种：

- **让行**：移动方按原路径行进，无事发生；
- **截停**：移动方停在阻挡者之前的一格，无事发生。

若协商无法达成一致，或双方一致同意，则进入**战斗**。

**攻击的唯一形态是战斗。** 系统中不存在独立于战斗的吃子行为。

### 2.6 战斗（Combat）

交涉谈崩后的升级状态。处于交战状态的棋子称为参战者。

### 2.7 对话（Conversation）

棋子之间交换言语的机制。成员数为 2 的会话即为对话。

### 2.8 群聊（Group Conversation）

成员数大于 2 的会话。

### 2.9 object

存在于棋盘上的实体物件，由 JSON 文档描述。

### 2.10 墓碑（Tombstone）

棋子死亡后留在死亡地点的标记。

棋盘坐标以 `(行, 列)` 表示格子位置。

## 4. 回合流程

### 4.1 总流程

```
每个回合，对每颗棋子依次执行：

  1. 判定该棋子当前状态
       ├─ 休息中 → 休息计数 -1
       │            本回合不可移动；可交谈、可被交涉
       └─ 可行动 → 进入步骤 2

  2. 棋子决策（注入其视野与记忆）
       可选动作：
         a. 移动（含移动 0 格，即轮空）
         b. 邀请对话
         c. 不做任何事

  3. 若选择移动 → 执行路径结算（§4.4）

  4. 若选择邀请对话 → 执行会话建立（§6.2）

  5. 记录本回合产生的全部事件
```

一个回合内，每颗棋子最多行动一次。处于休息状态的棋子不行动，只递减休息计数。

### 4.2 观测

棋子每次决策前，系统将其**视野范围内**的状态直接注入其上下文：

| 棋子类型 | 视野 |
|---|---|
| 马 | 以自身为中心的 5×5 |
| 其他类型 | 以自身为中心的 3×3 |

视野之外的信息不注入。棋子只能依据视野内所见、以及自身记忆中的信息决策。

**观测采用直接注入，不使用工具调用。**

### 4.3 移动与休息

| 项 | 规格 |
|---|---|
| 移动规则 | 按棋子类型的走法行进，可移动任意合法距离 |
| 休息回合数 | 取水平位移与垂直位移中的**较大者** |
| 马的休息回合数 | 固定为 **3** |
| 轮空 | 移动 0 格，休息 0 回合，随时可再次移动 |

示例：车从 A1 移动到 H1（位移 7），休息 7 回合；象从 A1 移动到 E5（位移 4），休息 4 回合；马跳跃一次，休息 3 回合。

**路径的语义是瞬时通过**：棋子只存在于落点，不在路径中途停留，也不持续占据路径。

### 4.4 路径结算

移动方沿路径逐格推进，遇到休息中的棋子时触发交涉。结算顺序为**路径方向顺序**：

```
对路径上的每一颗阻挡棋子，按由近及远的顺序：

  1. 判定交涉类别（§2.5）
  2. 执行交涉
       ├─ 让行 → 继续检查下一颗阻挡棋子
       └─ 截停 → 移动方停在阻挡者之前一格，本次移动结束
  3. 若交涉谈崩 → 进入战斗（§5）
```

**阻挡者拥有一票否决权。** 若路径上任一阻挡棋子不放行，路径即在该处终止，移动方停在其前一格。这与阻挡者的类型强弱无关——一颗兵可以拦下一颗后。

**路径目标格上已存在棋子**时，移动方仍可选择让行，效果为**两子同时占据同一格**。同格是合法状态。

**两颗棋子进入同一格**时，两者进行一次**平等交涉**，由交涉决定：

1. 同时占据该格；
2. 其中一方让步，退到原处；
3. 谈崩，进入战斗。

**同格的多颗棋子被视为一个整体。** 当路径交涉的对象是同格的多颗棋子时，按单一交涉对象处理，交涉规则与双人交涉相同。

**整体化仅在判定与规则层面生效，不干涉对话内容**：同格的每颗棋子仍然分别发言、分别听闻、分别记忆。

## 5. 战斗

### 5.1 触发

交涉谈崩。

### 5.2 参战

**所有处于交战状态的棋子都是参战者。** 参战人数不设上限；两颗、三颗或多颗棋子共用同一条判定路径，不存在代表制。

### 5.3 进行方式

战斗按回合推进，最大回合数为 `max_round`（默认 4）。

```
每进入一个战斗回合：

  1. 叙事 Agent 生成该回合战况
       输入：每个参战者各自记得的版本
             + 当前局面
             + 本场已生成的叙事
       输出：本回合的战斗叙事

  2. 将战况重新注入每个参战棋子
  3. 每个参战棋子决定：认输 / 继续
       ├─ 有人认输 → 战斗提前结束，进入胜负结算
       └─ 无人认输 → 进入下一回合

  达到 max_round 仍无人认输
    → 战斗结束，由叙事 Agent 根据已生成的结果认定胜者与败者
```

### 5.4 判定

**胜负由第三方叙事 Agent 做前向叙事推论决定。** 系统不引入掷骰、权重或数值裁决。

判定的输入必须是**每个参战者各自记得的版本**，而不是客观事实汇总。各方记忆的相互矛盾是视角分化的体现，属于应当保留并利用的素材，不得在输入前被对齐。

系统不追踪战斗状态：没有生命值、伤势字段或位置变化。战斗态势只存在于已生成的叙事文本中，叙事 Agent 每回合重读自己先前生成的内容并在此基础上前向推进。

### 5.5 加入

交战状态广播到**附近 5×5 范围**。范围内的棋子可以加入战斗并改变结果。

### 5.6 战斗期间的移动

**交战期间参战者不能移动。**

### 5.7 胜负结算

战斗结束后，由胜者向败者发起交涉。胜者可以提出各种条件（如改变颜色、成为仆从等），败者可以对这些条件再交涉。

**胜者拥有杀死败者的权力，这是谈判的前提。**

## 6. 对话

### 6.1 发起

处于可行动状态的棋子可以向**视野内**的棋子发起对话邀请。

**邀请不可拒绝**，被邀请方必须进入会话。

每颗棋子每个回合仅能发起一次邀请。**邀请被对方当场退出，额度照常消耗。**

### 6.2 建立

邀请方与被邀请方进入同一会话。

若被邀请方已处于其他会话中，则**视该会话的全体成员为一个整体**，本次邀请等同于邀请该整体。

### 6.3 退出与解散

- 会话内任意成员**有权立即退出**；
- 会话只剩一名成员时**自动解散**。

### 6.4 发言

| 项 | 规格 |
|---|---|
| 发言顺序 | 发起人先发言，之后所有成员自由发言 |
| 回合内可见性 | 后发言者可见本回合先发言者的内容 |
| 单句 CoT 上限 | 1000 token |
| 单句输出上限 | 100 token |
| 发言冷却 | 单个 Agent 的发言之间存在短暂冷却，防止独占发言 |
| 单会话总条数上限 | 50 条 |

**50 条为按消息计数，非按回合计数。** 成员知道该上限存在。

### 6.5 群聊

任意会话成员可以提议将视野内的另一颗棋子加入当前会话。**需当前会话全体成员一致同意，任一人反对即失败。**

该流程可重复，成员数不设上限。

### 6.6 踢出投票

任意会话成员可以发起投票，将会话内任意一名其他成员踢出。

- 每位成员在一次会话中**最多发起一次投票**；
- 表决者为**除发起者与目标之外的全体成员**；
- **全体表决者一致同意**则投票生效，目标被移出会话；
- 否则投票失败，会话继续。

## 7. object

### 7.1 定义

object 是存在于**实在层面**的物件，由 JSON 文档描述其**名称**与**说明**。

**Agent 不能创生或毁灭 object。** object 的存在与状态由系统维护。

### 7.2 状态

| 状态 | 可见性 | 行为 |
|---|---|---|
| **掉落态** | 可见，位于某一格 | 棋子移动至该格时可以捡起 |
| **携带态** | 不可见 | 随携带者移动 |

### 7.3 操作

| 操作 | 条件 | 效果 |
|---|---|---|
| 捡起 | 棋子位于掉落态 object 所在格 | object 转为携带态 |
| 丢弃 | 棋子携带 object | object 在棋子当前所在格转为掉落态 |
| 转交 | 接收方在视野内 | 所有权变更 |

### 7.4 棋子死亡

携带 object 的棋子死亡时，其携带的 object 在死亡处原地转为掉落态。

### 7.5 设计意图

object 是**世界事实，不是奖惩机制**。系统不声明任何 object 是重要的、珍贵的或值得争夺的。object 的意义完全由角色的价值观赋予：同一枚权柄，对不同棋子可以意味着合法性、压迫的证据、或毫无意义。

## 8. 死亡与目标

### 8.1 死亡

棋子被杀死后**退出游戏**。

**死亡只来自战斗后的胜负结算**（§5.7）。

死亡地点留下**墓碑**：

- 墓碑**非实体**：不可交互，不阻挡任何路径；
- 发现墓碑的棋子得知"**该棋子已在此处死亡**"；
- **墓碑不记录凶手。**

### 8.2 目标更新

**触发条件**，满足任一即触发：

1. 该棋子认定目标已经达到；
2. 该棋子认定目标已经**永远不可能**达到。

**判定权在棋子自身**，由该棋子根据自身记忆做出判断，系统不介入。

**新目标由该棋子根据自身记忆自行拟定。**

#### 8.2.1 缺少信息不等于永远不可能

"永远不可能达到"与"当前缺少信息"是两个不同的判定。

**示例**：一颗棋子立誓为被杀的同伴复仇，但不知道凶手是谁。这属于缺少信息，**不构成目标更新条件**。

此时目标的自然演化是替换为一个更前置的形态：

```
为同伴复仇  →  查明凶手是谁  →  复仇
```

由于墓碑不记录凶手，此类信息只能通过目击、对话或叙事推演获得。

## 9. 游戏流程

### 9.1 无终局

系统**没有胜负条件，也没有游戏结束条件**。

### 9.2 回合数

由使用者指定本段模拟的回合数（记为 `max_turn`）。达到 `max_turn` 后模拟暂停。

### 9.3 叙事编排

每段模拟结束后，由**吟游诗人 Agent** 编排该段回合的叙事。

编排可以继续：使用者指定新的回合数后，模拟从当前状态继续。

## 10. 实现要点

### 10.1 权威数据

系统持有并校验的权威数据只有三项：

1. 棋盘尺寸与格子占用；
2. 棋子的位置、类型、颜色、休息状态；
3. object 的状态与位置。

**记忆、性格、目标、动机、战斗态势都不属于系统权威数据**，由棋子各自的 Markdown 文档与叙事文本承载。

### 10.2 角色层与规则层的分离

规则层不写入任何价值判断。所有"什么重要""是否值得""应该有何感受"的判断均属于角色层。

**初始状态是设计的重点**：规则保持中立，因此叙事的张力来自初始角色之间的价值观差异，而非规则中的激励结构。

### 10.3 交互的开放性

对话内容与战斗叙事均为自由文本，不预设枚举的动作集合。系统的约束是结构性的（谁说、对谁说、时长、条数），不是内容性的。
