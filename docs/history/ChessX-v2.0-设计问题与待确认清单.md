# ChessX v2.0 设计问题与待确认清单

**日期**：2026-10-01  
**配套规格**：[ChessX-Spec-v2.0.md](ChessX-Spec-v2.0.md)  
**性质**：工程评审与规则取舍清单；这里的推荐方案不是用户的批准记录。

## 1. 评审结论与使用方式

现有设计可以实现成一个小型实验demo，核心思路不需要推倒。最值得补齐的是**规则边界与运行协议**：同一段话如何变成事实、角色到底知道什么、多人争议由谁决定、等待模型时如何暂停、已发生历史怎样恢复。

本清单不把和平收敛、角色误记、同场战斗重跑结果不同当作待修bug。这些与既定实验立场兼容。不重新建议忠诚度／仇恨值、棋力评估、骰子裁决、墓碑显示凶手或剧情导演强推冲突。

标记说明：

- **P0：实现相关规则前要决定**。缺少答案会产生不同世界行为，不能交给执行Agent自行猜。
- **P1：完整demo前要决定**。基础架构可先做，默认演示档可试验，但必须标注候选。
- **P2：可在首轮真实运行后调优**。主要影响实现成本或体验。

工程骨架、数据契约、信息投影、操作幂等和回放可先开展；未确认的规则集中到 `demo-v2-candidate`，不写成已批准默认值。每项确认后记录：决定内容、日期、rule_version、影响测试。

建议先处理 R01–R07、R10–R13；R08/R09/R14/R15 可以围绕一段具体模拟记录继续调整。回答时可以写“R05按方案A，R07调整为……”，不必重写整份规范。

## 3. 必须优先处理的规则缺口

### R01：兵和马没有足够完整的工程定义

**依据**：v1.0 §2.1说type只定义行进方式、颜色纯标签；§4.3沿用国际象棋走法；提及“如兵到底线升变”，但未定义方向／升变条件／选择权。马的路径与截停也未明确。

**问题**：兵的方向若跟颜色走，改色就改变移动能力，与颜色没有规则后果冲突。国际象棋的兵斜线走法依赖吃子，而ChessX没有吃子。马没有可逐格阻挡的物理L路径。

**推荐A**：兵有独立 `forward_row_delta=±1`；普通前进一步，斜前仅用于威胁几何；没有首次两格／吃过路兵；升变首版关闭。马只检查落点，没有中间路径。

**替代B**：完整保留兵方向和升变，但方向仍独立于color，显式定义首次两步条件／中间格交涉，到底线本人选后／车／象／马，升变不改personality。需要更多状态与测试。

**需要确认**：选择A还是B；若允许兵在空格斜前移动，明确这是ChessX自定义走法。type在交涉里影响威胁几何，但不代表强弱，更不决定战斗胜率。

**最小例子**：兵从 `(4,3)` 变白为青后，前进方向是否不变？正前方有人与斜前方有人分别怎样处理？

### R02：休息者“不行动”与“可以交谈”冲突，其他操作没有时点

**依据**：v1.0 §2.4休息不能移动但可交谈；§4.1又写休息棋子不行动；§7、§8定义物件和改色／目标，但主行动菜单只有移动、邀请、不做事。

**推荐A**：休息只禁move和主动invite；允许已有会话发言／立即离席／交涉与战斗回应；`pickup/drop/transfer/change_color/join_battle`是独立不移动主行动，每回合仍只提交一个。普通会话发言不额外送移动额度，也不占已有主行动。

**替代B**：休息中只被动回应，禁止物件操作、改色、加入战斗等主动动作；这些留到恢复可行动。优点是更严格的“长移动承诺”；代价是信使长移后不能及时转交刚送到的物件。

**需要确认**：尤其是休息中能否加入战斗、改色／转交，以及普通会话是否锁住移动。推荐会话中可以先离席再在本人主行动槽移动，防止邀请永久拖住别人。

### R03：回合顺序和额度影响故事，不只是代码风格

**依据**：v1.0 §4.1依次执行各棋子；§4.3休息回合数；§6后发言者看到前文；没有声明首位是否轮换，参战后提前结束是否补行动。

**推荐A**：配置顺序串行；rest在回合开始统一快照并减一；开始时rest>0本回合禁移动，即使减到0。进入战斗的角色本回合不补主行动，即使战斗当回合结束。保存每回合执行顺序。

**替代B**：每回合轮换首位，仍串行，降低固定首位偏差。它会改变遭遇与先发言优势，应成为另一实验档。

**不推荐直接切同时意图**：需要新的争格、同时会话、object竞争与观测快照规则，超出v1“依次决策”的小改范围。

**最小例子**：T1走2格，T2／T3休息，T4才能再移动。不要让“刚移动者尚未轮到扣rest”或“rest刚减0者立即移动”依角色数组位置区别。

### R04：路径上的轮空者、同格多成员和“退原处”

**依据**：v1.0 §4.4只写休息者阻挡；决定清单§2／§4包含静止／轮空者。v1.0既允许目标格让行同格，又要求进入同格平等交涉，可能被实现成双重谈判。

**推荐A**：当前路径上所有存活棋子都构成交涉对象，包括未轮到行动者；同格作为一个party。目标格只进行一次平等共处协议；初始同格作为已配置事实；退回原处只针对本次新到者。

**替代B**：仅rest>0者能阻挡；轮空者被无条件穿过。可实现，但会产生“为了阻挡必须先走动再休息”的行为结构，并与决定清单不一致。

**另需确认**：同格协议是否可以让现有居民退让到别处？若可以，要定义它退到哪、是否消耗主行动、是否绕过休息／战斗锁定。候选不开放这个未定义的额外移动权。

**最小例子**：A走向B、C同格。应是A与{B,C}一次群体协议、三个人分别发言；不是先B、再C、再全体共处连续三次交涉。

### R05：绝对否决与优势方单方面决定存在不可同时满足的冲突

**依据**：v1.0 §2.5“能攻击的一方单方面决定”；§4.4“阻挡者拥有一票否决权”“这与类型强弱无关，一颗兵可以拦下一颗后”。

**反例**：后A可威胁阻挡兵B，兵B不能威胁A。按优势规则A可决定让行；按绝对否决B又可禁止让行。一个最终结果不能同时满足两条授权。

**方案A（v2候选推荐）**：优势决定权优先，绝对否决表述改为“有决定权的阻挡者可截停；平等时任一参与者不同意则无法达成通行共识”。保留优势机制，但放弃“任何兵都能绝对拦后”。

**方案B**：阻挡者绝对否决优先；即使移动方优势也只能决定是否要求战斗或接受截停，不能强行通行。保留空间通行的绝对门槛，需要重写优势交涉的授权范围。

**方案C**：取消双轨决定权，所有通行必须双方一致；几何优势只提供给角色作谈判素材。最简单，但改变现有明确决定较大。

同时必须选：

- **双方都不能威胁**：推荐平等交涉；自动放行会绕过拦路者，也是一条新规则。
- **威胁几何是否看rest／遮挡**：推荐只看类型与移动前位置，不看rest／颜色／沿线实体。
- **群体能力怎么聚合**：推荐“存在任一成员可威胁对方任一成员”；平等结果全员一致，优势party内部一致。替代为“全员可威胁”会让群体混入一个兵就改变整体权力。

**需要确认**：A/B/C与上述三项。不要让执行Agent用一段提示词告诉后“你有绝对优势”，另一段又告诉兵“你有绝对否决权”，再由LLM随机决定谁的规则优先。

### R06：未走完整条路径时的位置、休息与战斗中心

**依据**：v1.0 §4.3休息按位移；§4.4截停前一格；§5参战者不能移动，但没有写谈崩时移动者到底在哪里。

**推荐A**：实际最终位移计rest；滑行子谈崩时停阻挡前一格，马落点冲突时留原点；战斗anchor=阻挡格；所有参战者保留各自位置，不自动同格。rest在战斗期间按世界回合继续递减，battle lock独立存在。

**替代B**：rest按请求距离，失败远行也承担代价。行为上更强调承诺与冒险，但这不是可以从“位移”二字唯一推出的解释。

**边界**：截停前一格可能已有此前放行者。候选视其放行许可包含本次停留；若要求新同格谈判或退到最近空格，要规定有限回溯算法，避免交涉递归循环。不能把马留在一个虚构L路径中间格。

**需要确认**：实际距离还是请求距离、马失败是否休3回合、战斗期间rest是否冻结、之前通过格的停留许可。

### R07：战斗时钟、加入窗口与战斗重叠

**依据**：v1.0 §5每战斗回合推进、附近可加入，但未说明是不是同一世界回合内嵌套跑完4轮。

**推荐A**：battle创建后的下一世界回合开始推进；每世界回合最多一battle round；附近者在自己的主行动槽加入；加入不传送位置，资格要求在anchor5×5内、存活且不在另一战斗。

**替代B**：一个世界回合内完成4轮，轮间给所有附近者加入机会。世界其他移动冻结，叙事节奏更集中，但要引入额外反应额度，且“持续4回合”不再表示世界时间。

**重叠处理推荐**：新冲突只涉及一场活动战斗，加入它；涉及两场活动战斗，合并成新battle ID，成员取并集、旧战斗历史按来源保留、位置不变。新anchor是新冲突格；剩余轮数取两场剩余轮数的较小值、至少1，不刷新已耗尽的预算。裁决只在合并后的成员上产生；已进入战后结算的战斗不能再合并。

**代价**：合并改变广播中心，原先远处参战者仍留场；叙事者需要理解此前两条各自历史，而不是虚构双方此前已经共同交战。必须提供合并回归样例。

**替代处理**：禁止打断活动战斗、自动截停外来移动，但这增加了免打扰规则，会减少介入可能。另一种“规则未支持就暂停”只可临时用于候选原型，不算完整demo验收。

**需要确认**：A/B、是否允许休息者加入（联动R02）、是否接受显式合并，以及合并轮数／广播中心。八子规模允许最多四场不重叠双人战斗，不能凭实现省事限制为全世界只允许一场。

### R10：N人战斗必须有明确的胜败集合

**依据**：v1.0 §5.3有人认输全场结束，§5.7胜者处置败者；没有多人分区或第三方败北代价。

**推荐A**：叙事Agent输出非空winner集合与非空loser集合，互斥且覆盖全体参战者；认输者必须loser；其余人的分区仍由叙事推论决定；加入者可失败并受到同等处置。

**替代B**：允许winner／loser／neutral或draw。更开放，但要定义平局时移动怎么结束、谁有执行权、object和承诺怎样结算。不能只增加一个“平局”字符串而不补后续状态。

**最小例子**：A与B冲突，C后来加入，B认输。C既可能与A共同胜，也可能与B共同败；“B认输所以A和C自动胜”不是现有规则已经确定的结论。

**需要确认**：是否允许平局／中立者／全败，以及第三方加入者是否同样可能被杀。无须加入数值风险惩罚，失败后果本身已影响角色的主观判断。

### R11：战后处置的开放语言与有限执行

**依据**：v1.0 §5.7胜者提条件，败者继续交涉，胜者能杀败者；没有多胜者权力冲突、停滞收束、强制服从语义。

**推荐**：自由条件始终允许，系统仅执行本人改色／转交／丢弃等已定义操作；仆从是承诺而非锁死人格。胜者只有本场对败者的处置权，不能杀未参战者。结算2轮后再给胜者一个终止许可，必须选择release或execute；调用失败技术暂停，不默认死亡。

**多人处置需要选择**：

- **A（v2候选）**：任一胜者有权处决任一败者；任何胜者释放一个败者就对整场生效。先提交者产生事实，顺序影响结局。
- **B**：任何胜者有处决权，释放须全体胜者一致同意。偏向保留各人的权利，但更难获得释放。
- **C**：释放和处决都要全体胜者一致同意。减少顺序偏差，但可能无法收束。

**无决定的处理**：v2候选档增加有限终止许可，由记录顺序的第一名胜者作最终选择，逐个处理败者；若不接受这个新增约束，替代方案先停在 `SETTLEMENT_PENDING` 等待继续结算或另一明确规则。有效选择缺失或技术故障时必须暂停，系统不替角色作生死决定。不要让“胜者总可继续谈条件”产生无限协议而耗尽demo。

**需要确认**：A/B/C、是否采纳有限终止许可、仆从是否仅为角色承诺。若希望强制服从状态，需要重新定义角色自主权，不是补一个 `servant=true` 就能合理实现。

### R12：信息不对称目前有三处容易误解

**依据**：v1.0 §2.1公开JSON全局可见、私人资料只本人；§4.2视野外不注入；§5.3／5.4叙事者读各方记忆；§9.3吟游诗人编排。

**缺口一：全局可见 vs 局部观测。** 若把全员初始坐标送进角色prompt，盲移的未知性会显著减少。

推荐角色只有相遇后局部身份／位置，研究者看全局公开配置；替代为开局全员知道静态名册（可不含坐标），之后动态位置局部可见。需要特别确认是否所有人一开始就知道所有其他角色存在。

**缺口二：说出来的话谁能听见。** 推荐普通／交涉／战后台词只送当条参与者；附近人默认只见结构变化，战斗anchor5×5收到活动通知，不听全部战况。可以设近邻旁听，但必须另定义听觉半径和object转交可见字段。

**缺口三：叙事者读秘密后可能泄露。** 角色记忆文本可能写隐藏计划；若叙事者把它写进公共战况，其他参战者会知道不该知道的秘密。

- 推荐特殊叙事者可读每个参战者自己记得的版本，保持矛盾；不读其他人的档案／记忆。输出时不得披露其他人的私密来源，保存内部版与角色可见版。
- 更强隔离方案：各角色先提供本场可分享的本人回忆，只把分享稿给叙事者。它降低信息泄漏，但缩减裁判可见的私人记忆，改变原始设想。
- **不能承诺仅靠提示词完全避免语义泄密**。字段投影可防直接泄漏，模型可能从内部读到的秘密改写成公开暗示，需要样例与人工抽查。

推荐吟游诗人成稿只给研究者，不回灌棋子，否则全知叙述成为新全员广播渠道。研究者全知导出和普通观众导出分开。

**需要确认**：开局名册／坐标、台词旁听范围、战况公开范围、叙事者秘密读取权限、成稿是否回灌。墓碑只给身份与地点这一已定规则仍保留，不再次问是否显示凶手。

## 4. 完整demo前要选的协议和内容取舍

### R08：多久算谈崩，技术失败不能算冲突

**依据**：v1.0写协商无法一致则战斗，但缺乏截止点。没有截止点会永久对话；把超时当反对会让网络故障导致角色死亡。

推荐每次交涉最多2轮全体发言，全部结果明确一致可提前结束，否则有效完成第2轮后谈崩；双方同意战斗可提前升级。格式／网络失败进入技术暂停。协议要求结构结论，台词内容自由。

替代：更多轮数、更开放的临时停止而非战斗。应按真实样本调整轮数，并记录这是通行交涉规则变化。普通会话50条上限不能自动代替交涉收束规则。

### R09：自由发言与会话合并有隐藏边界

**依据**：v1.0发起人先说后自由发言，又要求后者见前文；会话邀请整体、加人一致同意，但没有双方已在会话的合并规则。

推荐用轮转许可：每人每世界回合最多1次，可pass／leave；逻辑冷却防独占，不让墙钟影响世界。两人pass的完整空轮也要有记录或计数，建议连续2空世界回合自动关闭会话。

合并推荐建立新ID，保留双方已耗消息条数和踢人发起额度；新成员不收到入场前另一个会话的台词。加人目标已在别处会话时，先就“整个群体”取得当前成员一致同意。合并使新会话达到50条则关闭，不刷新免费发言额度。

替代：只允许无会话者邀请，或将邀请理解为旁听另一个会话而不合并；两者改变整体邀请语义。

推荐移动自动先离席，远处被整体邀请／合并者仍可说话但不知道别人最新坐标。若要超距自动散场，需要明确距离阈值和时点。

**已定项不重复确认**：两人踢人表决者为空，按决定清单是空操作；不是自动踢出。邀请后立即离席仍消耗邀请额度。

### R13：物件操作应独立，接收与视觉需清楚

**依据**：v1.0 §7允许捡起／丢弃／视野内转交，携带态不可见；主行动未包含这些动作。

推荐独立主行动、不自动捡；一次一个操作，不并列move＋pickup＋transfer。本人知道库存，其他人视觉不知道。转交无需接收者同意，它可以之后丢弃；双方知道交易物件，附近只看到动作而不附完整背包。

替代：移动落点可附带pickup；转交可拒绝。前者需要定义同格多人拾取竞争，后者需要有界接收协议并说明动作额度。

“不创生／不毁灭”意味着首版不存在烧毁物件等结构动作；自由台词可以如此声称，但物件仍在。是否希望“谎称毁灭”作为故事素材，无须另加奖惩机制。

### R14：自省机会与目标替换不是同一规则

**依据**：目标达成或永远不可能达成由本人认定；决定清单仍留人格锚点、防无限复仇待补。

推荐原始人格／背景作为只读初始锚点，目标另存版本；每5回合及会话／战后结束或死亡知识到达后有一次整理机会。自省不会自动替换目标；在同一目标下寻找前置任务叫refine。

推荐不在世界规则中限制复仇链深度、不设仇恨衰减；完整记忆历史保留，但当前上下文压缩。这种选择保留角色永不放弃的可能性，需要在实验中观察是否导致单调叙事。

替代：允许人格长期成长并修改某些锚点；需要逐条指定哪些能改、谁有写权限、怎样保存版本。不要让普通memory summarizer无意间把“重视承诺”改写成“只重视胜利”。

### R15：CoT硬上限和吟游诗人事实性不能按原文直接保证

**依据**：v1.0 §6.4要求CoT≤1000token；§9.3要求编排，但没有输出引用协议。

推荐不要求完整隐藏推理链，对支持的模型配置reasoning预算；不支持的记录无法强制执行。只要解释时输出简短私有reason_summary，不进入公共台词。普通台词完整校验后一次提交，UI仍可打字呈现。

推荐吟游诗人段落有event_refs，默认不读全体秘密；引用ID和区间可代码校验，事实支持关系抽查。不能声称“有引用所以绝不编造”，更不能把主观指控因引用了一条台词事件就升级为客观事实。

替代：真实流式台词、全知文学成稿。可以做，但需要专门保密／完整性解析器，或明确全知稿件仅为研究者阅读，且不改世界／角色知识。

## 5. 工程方案与首轮调优

### R16：本地架构、模型与资源投入

当前目录没有需要沿用的ChessX应用代码／既定技术栈。推荐Python FastAPI＋React TS＋SQLite单机实现，服务端世界执行器独立于页面生命周期；不照搬参考项目的账号、支付、Postgres、MinIO与多模态栈。

全TypeScript也可保留相同分层与契约。需要确认最终实现语言偏好、可用模型提供方、期望本段回合数、单段可接受等待／预算。此时不需要先购买服务或配置密钥才能写规则内核与固定响应测试。

v2暂设工程起始预算1000调用／200万token／30分钟，不是预测真实花费。模型调用前应预留预算；隐藏计费和不可取消在途请求导致金额只能估算。真实模型与价格应在实现时按选定提供方核实，不沿用旧评审中推理模型单局价格。

初始执行顺序固定、模型并发1、一个活动世界最容易验证。吞吐优化应在2人→4人→8人实测之后进行，不先把最多八子的demo做成分布式Agent平台。

## 6. 已在v2直接修正的工程问题

以下不需要为每条另外批准，因为它们是确保既有规则能可信执行的工程要求。

| 问题 | 影响 | 修正 |
|---|---|---|
| 世界“只三项权威”忽略成员／存活／协议 | 无法禁止死人行动或确保只在本场战后杀败者 | 区分结构权威、发生记录与主观文本；不增加战力数值 |
| 私人Markdown被当可全局读取文件 | 隐藏目标泄漏，角色变全知 | owner投影、单一ContextBuilder、收件快照；研究者输入与角色输入分开 |
| LLM返回即直接改状态 | 非法ID／物件复制／同槽重复提交 | Intent schema＋业务权限＋原子事件提交 |
| 主循环依附React页面／浏览器存储 | 刷新和关闭页面打断世界、存档不完整 | 服务端执行器、操作表、checkpoint、可恢复cursor |
| 暂停只停止字幕，旧请求仍返回 | 续跑或重置后写入旧世界结果 | generation校验与取消；提交前再次检查 |
| 台词按文字去重 | 两句相同“不对”被合成一句 | slot＋位置身份；传输重发与内容重复区分 |
| 模型异常兜底为沉默／同意／认输 | 技术故障改变人物选择或触发死亡 | 有界重试；失败暂停；有效pass才代表沉默 |
| 全局账本当角色长期记忆 | 角色知晓未在场事件或当前盲区状态 | 实际收件归档＋本人主观记忆；检索先按owner过滤 |
| 记忆任务启动即标完成 | 模型失败后永远丢失这段经历 | pending job到文本版本原子提交后才完成 |
| 回放重新调用模型 | 原故事无法复现、审计无法对齐 | 折叠已提交结果；重生成是另一实验 |
| 只测秘密“未出现” | 合法证据漏传也会毁掉行为 | “应有／不得有”双向上下文测试 |
| 吟游诗人把话语当事实 | 指控变成客观死亡／物件变化 | 事件类型、主体来源、引用与语义抽查 |

## 7. 应记录为实验风险，不宜硬加规则修复

| 风险 | 为什么需要观察 | 推荐证据／应对 |
|---|---|---|
| 和平收敛或长期轮空 | 初始角色可能都偏向协商，系统无奖励刺激 | 比较价值观冲突与相容场景；不自动制造敌意 |
| 64×64遭遇稀疏 | 最多8人、局部小视野，空回合可能很多 | 默认演示8×8；大棋盘标稀疏探索；用实际遭遇日志，不把面积比例直接说成每几局概率 |
| 类型刻板印象 | LLM会把王看成领导、兵看成弱者 | 人设与type交叉场景；prompt说明type只影响几何，不赋战力 |
| 叙事者胜负偏差 | 长回忆／先输入者／某类措辞可能更易获胜 | 同场不同输入顺序对照，保留前文与裁决解释；不偷换骰子方案 |
| 历史越长越难注入 | 八人各自记忆、战况、会话共同增长 | 实测token、分开私人归档与有界输入；整理不能静默丢任务 |
| 固定行动／发言顺序优势 | 先行动者改变后者观测，最后者能见前文 | 记录顺序，单独用轮换档做对照 |
| 模型看似自主却被指令牵引 | 强调“故事要精彩”可能直接制造冲突 | 基础prompt不要求戏剧化或特定结局；保存正式输入链供审查 |
| 事实回放正确但成稿不忠实 | 文学润色可能制造未发生行动或秘密 | 事件引用、来源标记、抽查；成稿不写回模拟 |

**特别澄清旧材料中的两点**：

1. “没有数值就无法做动机干预实验”不是必然成立。可以固定其他因素、只改一条目标／性格文本并重复运行；但这检验文本干预及其表述效应，不能宣称精确测得一个连续的忠诚度因果系数。
2. “移动后休息d回合”在瞬时落点语义下是**移动后不能再移动**，不是d回合后才抵达。角色可以立刻到远格、但之后无法继续移动；相关叙事与UI不能写成仍在路上。

## 8. 确认后的更新模板

```text
决定ID：R05
选择：方案B，阻挡者绝对否决优先
补充：优势方可选择接受截停或要求战斗，不能强行通过
决定日期：YYYY-MM-DD
rule_version：2.0-approved-01
更新：规格§7.2、profile、T06及双向信息测试
```

实施前先确认影响几何、时间、通行权、战后生死与信息边界的P0项；然后用短局验证P1的协议节奏。模型价格、预算和调度吞吐在真实运行数据上调整。
