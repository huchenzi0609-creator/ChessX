# 上下文压缩、长期记忆与空间认知

实现与修订日期：2026-10-03。本文描述角色上下文的工程机制；冻结 `ChessX-Spec-v2.1.md` 是历史基线；当前用户批准的demo-v2.2及版本升级约束见 `EXECUTION_POLICY.md`。历史维护默认使用本地确定性摘录，不调用模型；角色的主观记忆与目标反思另行执行。

## 要解决的问题

旧实现将最近30条收件作为模型输入，输入超额时还会继续删除最老记录。记忆阶段虽检查从旧水位起的所有收件，却没有把这个完整范围提供给压缩请求；成功后仍把水位推进到全部收件数量。因此，一些从未进入压缩模型的消息也被标为“已处理”。短摘要每次整体替换，还可能把先前知道的重要事实省略掉。

空间方面，角色能在即时观测中看见静止人物，但此前仅从移动、死亡收件重建旧位置；离开视野后，之前的会面位置便可能丢失。部分交谈阶段还没有导航上下文。记忆和导航应在工程层面提供连续性，不能只要求角色“记住”。

初版滚动压缩仍把模型整理历史作为下一次主行动的前置条件。实际服务即使只整理一条收件，也可能返回超过1000 token的推理；缩小批次并不能保证合规，重复尝试还会额外付费。因此，当前把收件索引维护与角色模型反思分开。程序只保留已收到的原话和已投影的规则回执，不作角色推断、不替角色选目标，也不将不合规模型响应截短后宣告成功。

## 参考与取舍

- [LangMem 的滚动摘要实现](https://github.com/langchain-ai/langmem/blob/main/src/langmem/short_term/summarization.py) 使用 `RunningSummary` 保存摘要、已处理消息ID与末尾消息水位，并将摘要和未压缩的近期消息组合。这里借鉴增量范围和近期原文缓冲；不照搬其超额输入时裁掉旧消息的路径，以免遗漏尚未处理的信息。
- [OpenHands 的 LLMSummarizingCondenser](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py) 保留初始锚点与近期后缀，以事件ID描述压缩范围，并区分容量压力和一般维护触发。这里保留人物设计、当前规则与目标，压缩角色收件中的旧前缀；不引入代码执行工具或独立 Harness 依赖。
- [OpenAI Agents SDK 的压缩会话实现](https://github.com/openai/openai-agents-python/blob/main/src/agents/memory/openai_responses_compaction_session.py) 对失败、取消和并发代际提供替换恢复。这里借鉴一致性要求，使用现有本地事件存储、操作身份和提交校验；不使用其专属 `responses.compact` API。
- [LangGraph 记忆概念](https://docs.langchain.com/oss/python/concepts/memory) 区分短期上下文、长期语义信息与经历。这里将滚动摘要、重要信息账本及原始收件归档分开，全部以当前世界和角色为归属边界。

这些来源提供机制参考，不保证摘要语义绝对无损。本项目仍需针对遗忘、误传、过期方位和恢复中断做回归检查。

## 记忆结构与两种整理方式

1. **初始人物锚点**：冻结人物 Markdown、共有纪律与当前目标。运行中保持来源和权限，不将人物资料裁成摘要。
2. **主观记忆**：`memory` 保存角色模型自己的记忆与判断，具有独立版本。程序整理历史时不覆盖此字段，也不改变当前目标及其版本。
3. **近期原文**：容量维护通常保留近期12条原始收件不进入前置整理；角色决策使用未整理收件的至多30条语义窗口及单独的近期对话窗口。正常记忆阶段会分批覆盖该角色全部待处理范围。输入紧张时可缩小可重建的提示窗口，原始记录不删除。
4. **摘录索引**：`rolling_summary` 在默认模式下保存至多350 token的完整摘录或来源指针，通过专用 `evidence_index` 注入，与主观记忆分开。长记录改用明确指针，不把原话裁成可能丢失否定或条件的半句话。索引不出现某条旧消息，不表示该消息被删除。
5. **长期账本与收件归档**：默认逐条保存所有有效收件的完整原话或结构化回执，并保留角色、回合、说话人及来源。同样的台词由不同人、不同回合说出时，条目按角色与回执ID区分。重要性标记只用于检索排序，不作为删除条件；旧有模型提取条目仍保留。

“有效收件”指允许进入角色认知且有信息含量的记录。纯回合节拍等维护记录不挤占语义整理额度；无台词的交涉决定、投票、物件转交接受或拒绝仍有信息价值。每次本地维护最多处理128条有效收件，按最老未处理前缀推进，避免一次步骤承担全部旧历史。

`CHESSX_MEMORY_COMPACTION_MODE=extractive` 为默认值，本地维护不调用生成或能力探测API，不创建模型结果或公开CoT，不增加API调用／token用量。其来源标记为 `extractive_receipts_v1`，含义是程序整理已收材料，不能被解释为角色模型作出的信念或目标决策。

显式设置 `CHESSX_MEMORY_COMPACTION_MODE=llm` 可选择原模型摘要路径。该模式使用默认4条、可配置1–32条有效收件、1800 token原文软阈值与6144输入预算，仍要求真实模型公开CoT且至多1000 token。推理超限时最多三次额外缩批纠错，格式／来源错误最多三次尝试，全部计入运行预算；持续不合规时保留进度暂停。该模式不作为默认恢复方案。

角色请求组合当前观测、近期原文、滚动摘要、相关长期信息和导航上下文。归档检索限定在该角色自己的收件及记忆中，依据当前人物、发言、目标和未决事项选取相关信息；无需 embedding，也不为每次检索额外调用模型。

## 覆盖水位与持久化

覆盖水位是“这一连续范围已完成相应整理并持久提交”的证明，而不是当前收件总数。默认模式使用独立的 `extractive_watermark`；旧LLM覆盖水位不证明对应回执已被逐条索引，首次切换默认模式从0建立摘录。提交成功后，同步 `compaction_watermark` 供近期上下文确定未整理窗口。每批具有固定覆盖范围和来源ID；索引、账本增量、真实水位与运行游标一起提交，下一批从实际覆盖末尾继续。

事务失败、取消或提交代际过期时，不修改持久索引、账本和覆盖水位。重试继续尚未完成的范围。原始归档不因整理被删除，也不允许旧任务覆盖新代际的收件或状态。显式LLM模式的模型失败、规则校验失败及预算耗尽同样不能推进覆盖水位；模型等待不持有数据库事务。

本地摘录维护只建立证据索引，不代表一次模型操作。已成功提交的索引不会因后续角色反思失败而回滚。模型容量不足时可调整可重建的提示窗口，不能将从未整理的旧消息虚报为已覆盖。

`reflection_watermark` 与 `last_reflection_turn` 分别记录成功角色反思的收件范围与回合，不与摘录水位混用。正常MEMORY阶段先分批整理全部待处理收件；每五回合或新收到死亡、会话结束等重要规则事件时，再执行原 `memory` 模型阶段，对当前主观记忆和目标作一次有来源的反思。同回合重新进入不会重复已完成反思。目标替换仍须由真实模型给出已达成或确实不可能的理由，不能因程序摘录或信息缺失自动改目标。

反思请求保留公开CoT、1000 token推理上限、1024 token正式输出上限及有界纠错。真实反思或决策持续不合规时仍暂停；修复历史维护不能承诺服务商永远返回合规推理。提示中可用来源限定于该角色实际获知且实际提供给这次请求的材料。

反思有专用引用协议：后端从本人检索候选中选取至多6份完整已投递回执，放入不可被裁掉的reflection_sources，移除重复索引／检索展示；protocol.allowed_source_receipt_ids与输出schema枚举使用同一组角色ID:数字序号。仅这些值可进入source_receipt_ids，记忆索引键和世界事件ID不作别名推断。每次重试保留完整来源和白名单；没有已呈现回执支撑的初始知识或原主观记忆反思可用空数组。该窗口不删除持久来源。反思反馈引用本协议，不使用可选压缩器的source_batch。

输入紧张时先紧凑表示全部已知位置：保留姓名、坐标、观察回合、可见性、旧见性质、状态、来源类型和方位／距离，省略可由当前坐标及回合重算的增量、时效、距离分段和重复日志ID。完整来源仍持久保留。移动示例、接近路线、到访及路线展示副本可按完整记录缩至零，明确标记缩窗；完整合法几何目标、当前观察、权限与待决移动接触不省略。随后才缩小历史／检索副本，最新证据不截成半句。人物设计、当前目标、主观记忆与待压缩原文不静默裁掉，不通过提高预算上限绕过检查。

## 知晓与事实的边界

每项长期信息保留可追溯来源及角色归属。完整账本及空间记录存于本地 `data/chessx.sqlite3` 的角色私有状态和事件快照，与索引、水位一起原子落盘；观众投影及吟游素材不读取这些私有条目。模型输入中的来源仅保留首条和最近三条样本及总数，完整来源不截断，防止同一事实反复引用挤爆窗口。超过提示显示长度的条目使用来源指针，不生成半句引文。角色听到“波吕波斯已经去世”，可长期知道“报信人告诉过我这件事”；这不自动等同于规则引擎证明波吕波斯死亡。亲见、传闻、收到的战斗叙述、个人判断和相互冲突的说法必须能够区分。

记忆编辑只允许引用该角色实际收到的记录，不能使用全知事件、其他角色的私有资料、未参与的对话或吟游诗人成稿补出知识。来源ID用于专用结构字段，不能进入角色台词。保留重要信息并不禁止角色撒谎、隐瞒或怀疑；它保证角色仍有可用的认知依据。

## 空间认知与有目的的行动

所有角色阶段提供适用的空间上下文，包括普通会话、交涉与结算。它解释当前位置、坐标与东南西北、相对方位、距离、本人实际来路和到访位置，以及可见他人的位置和最近见到位置。

空间记忆由角色当时实际 `observe` 所见和本人合法收件更新。静止人物同样可以留下“我在某回合某处见过他”的记录。离开视野后，记录标为历史位置并显示时效，不追踪未见到的移动。当前可见位置与最后见到位置不能混作实时定位。

方位采用棋盘行向下增长为南、列向右增长为东的统一约定；距离描述仅代表空间远近，不保证路线畅通或人物仍在那里。地点传闻是带来源的语言线索，不能变成隐藏人物的实时精确坐标，也不能从原作、名字或他人私有记忆猜出位置。

导航把目标与可执行动作连接起来：先考虑找谁、确认什么、靠近哪处已知地点或搜索哪个区域，再选择合法移动。当前几何选项、已知占格、可能发生的交涉、实际休息成本和最近等待情况同时提供。`toward_known_people` 将本人已知地点连接到每人至多两个能减少几何距离的合法下一步，显示移动前后距离及风险；休息时不提供可移动方案。候选只接近最后见处，并不保证人物还在那里。休息期间不能移动；需要与沿途或终点占格者交涉时，应认识接触目的，不能把每次路遇都当作调查会议。

这些内容提供决策依据，不强制角色移动，不替角色选择目标，不增加隐藏全局地图，也不改变交涉、视野、休息或棋型几何规则。旧位置不确定时，角色可以自然说明“我之前在西北见过他，未必还在那里”，继续核实或探索。

接近候选同时提供轴向误差变化：车或兵朝对角目标迈第一步时，即使最大轴距离暂时不变，缩短另一轴的合法移动也可作为下一步。交涉时，移动者还能看到自己已选的目的地和当前接触格，区分通行／终点共处；计划尚未提交，不把接触格记作已到访。阻挡者不会因此得到移动者隐藏的起点、终点或路线。

## 旧世界的兼容恢复

旧 `memory_watermark` 曾可能跨过未被压缩模型看到的记录，不能直接作为新覆盖机制的证据。默认摘录模式采用独立的新水位0，从本人历史收件逐条建立索引；先前LLM水位也不证明已有完整逐条摘录。旧主观记忆、目标及版本保留，旧摘要仍可从原快照回查；程序索引不把旧模型摘要当成原话。重要信息继续补入，人物设定与已完成对局事件不重写。

空间历史仅在一次性迁移时，按归档中的当时状态回放各角色的 `observe`，恢复本人曾见的人物位置。本人来路和到访格子则始终从本人实际移动回执重建，提议路线和交涉接触格不算已到访。绝不能拿当前全局棋盘补出过去知识。迁移结果带版本标记并持久化，避免每次请求重复回放；新运行按提交时的合法观测增量更新。

旧世界首次切换默认模式可能积累较多待整理历史；本地补索引不产生API费用，也不会推进棋子行动或世界回合。后续真正的模型反思、角色决策与吟游成稿仍会付费，继续遵守调用、token及时间预算。不要为了验证单个遗忘场景再跑50回合。离线回执和固定模型响应可验证覆盖、权限与恢复语义；真实服务的推理合规需要另行实测。

## 验证与观察范围

必要回归包括：早期死讯跨50回合仍可检索；超过一个输入窗口的旧消息逐批无跳过；账本不被后续索引省略删除；失败或取消不推进水位；来源越权被拒；传闻不升级为全知事实；静止人物离开视野后保留过期位置；交涉阶段具备方位；未知障碍不被预知；旧世界只迁移一次且恢复不推进回合。默认模式另须验证前置维护零API调用、单条残余收件不依赖CoT、同句不同来源独立保留、主观记忆与人物Markdown不改变、反思水位独立及反思失败不丢已提交证据。

本次集成的实际测试结果与真实API使用情况由主集成记录在 `docs/VALIDATION.md` 和 changelog 中。机制能减少工程性遗忘与空间失忆，模型仍可能作出犹豫、欺骗或错误判断，需以完整对局观察行为质量。
