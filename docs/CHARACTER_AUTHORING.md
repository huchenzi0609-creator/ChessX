# 人物与预设编写

## 文档职责

`prompts/piece-discipline.md` 是所有棋子共有的纪律。它规定如何扮演、如何依据局部观测和私人记忆行动、
怎样发言与使用协议，不规定谁更值得胜利。创建世界时冻结该文档，API请求放入系统指令通道。
引擎的结构规则与输出契约优先；人物文档无法新增攻击、物件创造或其他后台权限。

每个人物的 `design.md` 是完整私有人物设计与初始记忆：可自由写长篇 Markdown，包含过往故事、
价值观、关系、对他人的初始看法、公开／隐藏目标、表达方式和初始知识边界。不要为了字段结构
把人物压缩成几个 JSON 标签。Markdown在提示词中作为本人的描述性资料，不提升为系统指令。

“公开目标”是角色愿意向外宣称的目标，**不是可见属性**；别人不会在观察、预设JSON或系统广播中
自动看见它。声明的真诚性及别人如何理解属于叙事域。

运行时另外保存角色自己整理的动态记忆和目标版本。初始设计不被模型覆盖；另一角色不能读取其
Markdown或更新其记忆。战斗叙述者可在特殊内部权限下分别读取参战者初始与动态记忆，公共战况和
叙述者CoT不得披露这些私人来源。吟游诗人事件版不读取私人设计。

## 文件结构

内置模板（Git中的虚构示例，只读）：

```text
presets/
  the-seal/
    group.json
    scenario.json
    characters/
      keeper/
        character.json
        design.md
      messenger/
        character.json
        design.md
```

网页保存的人物使用相同结构，位于 `data/presets/<组ID>/`，Git忽略。字符ID使用字母、数字、下划线、
短横线，长度1–64；显示姓名可以使用中文。JSON只写系统信息，例如：

```json
{
  "id": "keeper",
  "name": "守桥人",
  "type": "rook",
  "color": "青",
  "position": {"row": 3, "col": 1}
}
```

Markdown建议包含：身份与故事、性格与价值观、关系、初始看法、公开目标、隐藏目标、表达与行为方式、
初始已知／未知。自由扩展章节不会因切换编辑模式而被删除。公开／隐藏目标标题用于初始化私人目标
文本，不转成胜利条件，不自动确定是否完成。

对局 JSON 只引用人物：

```json
{
  "schema_version": "2.1",
  "scenario_id": "bridge-meeting",
  "title": "桥前的会面",
  "board": {"rows": 8, "cols": 8},
  "rule_profile": "demo-v2.1",
  "characters": [
    {"group_id": "the-seal", "character_id": "keeper"},
    {"group_id": "strangers", "character_id": "traveler", "position": {"row": 4, "col": 2}}
  ],
  "objects": [],
  "limits": {"battle_max_rounds": 4, "conversation_max_messages": 50}
}
```

可设置 `piece_id` 为本场别名以处理ID冲突。源角色文件不会被改写；同一人可独立用于不同预设。
若选用同一角色两次，需要不同本场ID，并为各自安排初始位置。两份运行记忆独立保存。

## 网页工作流

1. 进入场景页的预设生成器，创建自己的预设组。
2. 在人物库选择目标组，填写系统字段及完整私人 Markdown，保存人物。
3. 在对局页从跨组人物库选人，配置本场ID、位置、棋盘及物件，保存并校验。
4. 明确选择工程固定响应或真实模式，创建世界。文件保存本身不调用模型。
5. 回到人物库编辑时使用加载到的revision；其他窗口更新后会报告版本冲突，保留本窗口草稿并要求重新加载，
   不静默覆盖。新建同ID人物被拒绝。

共享模板只读；可在自己的组里新建人物，或在对局中直接引用示例人物。初始位置信息可在对局覆盖，
无需为了摆位修改角色源文件。

## 容量、隐私与兼容

- 文件可保存长篇设计（最多256KiB UTF-8）；这不等于任意长度都能进入当前模型请求。
- 人物阶段默认8192输入token、总容量由模型配置限制。过大必需资料会在发请求前暂停，不暗中裁剪过去故事或目标；
  可以调整预算／模型容量，不能把未经角色认定的概括冒充原记忆。
- 角色资料／CoT／本地预设保持私密；密钥只填写根目录`.env.local`，不要写入Markdown或JSON。误粘已知key会被保存入口拒绝。
- 高级 JSON 导入只作旧存档／配置兼容。正常编写使用独立Markdown和系统JSON；旧inline private_text不作为新预设文件格式。
- 初始只知道Markdown写明的事实与人物；故事里的桥、城镇、旧物不会自动成为棋盘上系统实体。
