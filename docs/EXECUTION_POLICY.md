## 用户明确更改的规则

1. 普通会话从每棋子每世界回合最多一句改为最多 **10 句**。额度跨普通会话共用，合并、离开再加入都不能重置。10 是上限，pass、leave 和少说仍合法，不要求填满。每棋子最多 12 次普通语言许可，留出非发言操作并保证阶段能结束；取消、未提交的竞速草稿不算已发言。
2. 三类会话总台词限额为 **50 × 历史最高同时在场人数**。峰值单调不减，离开不会缩减上限。合并按原消息 ID 并集计数，不能洗掉已说台词。固定 `conversation_max_messages=50` 仅是旧规则参数，新局按峰值公式执行。
3. 所有棋子休息回合数取实际起格到实际终格的切比雪夫距离 `max(abs(dr), abs(dc))`。阻挡没有位移则休息 0；马成功跳变休息 2，路径仍只有起终点。休息限制按回合开始的快照生效。
4. 所有棋子即时视野统一为 **3×3**，边界裁切；马不再是 5×5。观测、事件路径投影及导航均按存档规则版本计算。

此前“一回合一句”的限制针对普通会话。移动交涉和战后善后需要在当前世界回合内解决，继续使用有限许可循环和各自结构操作；它们不会被一个外部 10 句计数卡在无法推进的当前回合。台词总量均遵守上述峰值公式。交涉的失败可导致战斗，普通关闭、善后处决／释放仍分别处理。

## 主流程与提交边界

```mermaid
flowchart LR
  S[START 回合权限快照] --> A[PRIMARY 各棋子一次主行动]
  A --> C[COMBAT 已存在战斗一轮]
  C --> D[ORDINARY 多轮自然会话]
  D --> M[MEMORY 本人证据维护与定期反思]
  M --> E[END 完成回合]
  E -->|继续本段| S
  E -->|达到本段目标| B[BARD 公开素材成稿]
  B --> P[分段暂停]
```

主行动先让角色选物理意图并维护私人计划，再将合法意图持久保存为 work，随后执行接触、移动或物件子协议。计划维护与 ActionChosen 同一次提交；实际移动提交后才记录计划进度。网络等待不跨数据库事务。事件、当时接收者投影、下一游标、私人变化和成功操作共同提交。

每次模型请求保存执行策略哈希、预期世界状态哈希、seq、generation；预算预估和竞速实际请求共用相同契约。返回后核对持久状态，暂停或策略变化后的旧响应不能进入世界。请求执行次数仍由供应商控制，取消不保证免费或 exactly-once。

## 私人计划与记忆检索

`private[角色id].travel_plan` 保存目的、动机、下一步、可选已知人物和自主选择的目的地，及创建／复核回合、版本、状态、实际进度。action JSON 可带可选的 `private_plan`：keep、revise、complete、abandon；省略或 null 保留旧计划，revise 必须有目的。引用可以为空，引用时必须是本次拟合输入明确提供、且属于本人原档案的 receipt ID。

人物目标只能来自本人当前观察、亲见记录、已交付身份或人物 Markdown 的既有认识。认识人物不带来坐标。到达过去见过的地点，不保证找到该人物；系统不会替角色选择目标、发起寻路或宣布完成。计划进度分别记录请求目标、真实起终格、几何距离变化和接触结果；谈话接触不被当成同格抵达。完成／放弃由角色明确决定，不重写目标反思或初始人物文档。

计划只在本人上下文及显式研究检查中出现，不进入观众事件、战斗叙述器、别人记忆或吟游素材。完整计划历史保留最多 12 条；请求副本先保留最近 3 条，预算压力时可完整省略历史，保留当前计划核心。

检索只处理本人原回执、长期账本、人物描述和本人可见／已知姓名。通用同义组帮助把死亡、身世、承诺、转交、位置等不同表达联系到既有证据；英文按整词匹配，避免 deadline 触发 dead。名字及别名来自本人数据，不引入全局角色名册。显式目标、最新话题及计划按主权重检索，近期闲聊仅作 0.2 权重背景，避免闲聊淹没新问题。

关系和承诺索引展示带归属的完整原话，不生成真实关系图，不自动判定承诺兑现或认定身份。说过、否认过、后来改变说法的证据各自保留。模型仍可能误读检索；这些机制提供来源，不机械保证理解正确。

新局共用纪律 v2 消除重复叙述规则并明确动态额度，私人长人物 Markdown 保持完整。action 正式 JSON 上限调整为 1024 token，以容纳独立计划；台词仍最多 100 token，棋子 CoT 仍最多 1000。重复导航说明和派生元数据也可按需紧凑投影；当前人物、目标、主观记忆、实际移动和所有已知位置不变。执行及纪律审计哈希保存在操作输入记录，不当作人物知识发送给模型。没有提高 8192 角色输入限制或运行预算。旧纪律快照不会被静默裁剪或替换。

## 战斗与吟游权限

战斗叙述和胜败读取参战者的当前 `memory`，它是主观判断，不包含 `initial_memory`／`persona`、goals、原始私人证据账本或计划。空主观记忆就是空；不能用人物设定补齐。当前参战名单、格子、已投降者及公开战斗发展仍由规则提供。主观回忆不得直接公布为战斗事实，处决仍只由善后合法操作执行。

吟游为当前段选取公开事实，同时在任务创建时冻结最多两段先前公开稿件的完整、有来源段落。最多六段文字、2400 字符；只有原始事件存在、属于本世界、确为公开且早于当前段的段落才可进入。超过限制整段省略，不剪掉否定或结论。预算压力可移除完整连续性段落及相应来源副本，当前段事件继续按原有无损分块处理。

先前稿件为连续性提示，原事件控制事实；旧说法可被当前新言论质疑，但不是程序自动认定的新真相。块稿与合成稿都只接受本次实际提供的原始引用。任务一旦创建，前段稿件重编不会漂移其输入。正文和引用不回灌棋子，吟游也没有固定稿长或 CoT 长度上限，仍受模型物理容量及本次预算约束。

## 版本升级、存储和维护

新世界冻结规则 manifest、执行策略、非敏感执行配置、提示与纪律哈希；服务商地址仅存身份哈希，密钥不进这些字段。服务端模型配置或提示版本发生变化时，旧世界不会悄悄续跑。网页先提供兼容性预览，显式升级前做本地数据库备份、校验 expected_seq，并递增 generation；升级前元数据留在 execution_history，历史事件和原始快照不改写。

**未完成旧协议是明确的兼容边界。** 旧档若有未完 work、故事 job 或在途模型请求，当前版本不强行升级或截断。可继续查看、导出、备份，或通过重置／新建启动新局；若要完成旧协议需要兼容原策略的程序版本。本轮没有实现用户搁置的完整启动恢复和跨版本协议迁移矩阵。

SQLite 格式自动升级仅加存储列，不自动更改世界执行策略。新日志每 50 个事件保存完整检查点，其余保存无损 JSON 差异；列表追加只存新增尾部。回放检查基底 seq、前后状态哈希，从最近检查点逐增量恢复；当前世界仍有完整工作状态。损坏增量不会被跳过或伪造修复。

旧全量日志只有点击压缩才在备份后事务转换；不删除历史、不自动 VACUUM。转换后数据库文件大小未必立即减少，空页可供后续写入复用。定期全量检查点仍重复增长中的档案，Store.get 仍解析完整当前世界，这次优化减少历史快照膨胀，并没有把无限长局存储变成恒定大小。

在线备份保存在 Git 忽略的 `data/backups/`，权限 0600，目录 0700，包含整个数据库并保留 WAL 已提交内容。删除只移除选定非运行存档及其操作、事件、文本版本和命令；预设与既有备份不删。网页要求输入该存档名称确认不可撤回的删除。备份是否保留、数量及磁盘空间仍由本机研究者管理，没有自动滚动删除策略。

## 网页与导出

观众实时状态通过 SSE 补发事件和安全快照，seq 对齐后展示，断线退回低频轮询。切换角色立即关闭观众流与清空旧视角缓存；本人只读取自己的投影与收件页，不复用全知 DTO。收件默认最近 200 条，会话默认最近 50 句，操作记录默认有限页；更早历史按需读取。故事列表传元数据，正文按 revision 读取，长列表设窗口。

预算面板区分本段请求／已知 token、等待原因、当前角色和尝试次数，以及世界累计未返回用量的请求。没有供应商费用数据时显示金额未知，取消或失败请求不能被解释为零成本。推理只在显式全知研究页面查看，系统叙事者／裁判／吟游的 actor_id 为空也可检查。

导出先取得一致的本地 SQLite 副本，再逐条写 ZIP，按块文件流下载；浏览器使用一次性本地下载地址，不把整包转 Blob。普通包排除私人档案与 CoT，研究包仅本机显式请求。文件流结束或失败清理临时文件；进程被强制杀死仍可能留本地孤儿文件。删除存档会撤销其已准备下载，但不会抹除既有备份或已下载副本。整库副本需要额外磁盘空间，流式处理减少内存，不等于零磁盘开销。
